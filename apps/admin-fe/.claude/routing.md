# Routing

## Route File Pattern

Route files in `src/routes/` are **thin wrappers only**. They must not contain component logic.

```tsx
// src/routes/(core)/users/index.tsx
import { createFileRoute } from "@tanstack/react-router";

import { UserListPage } from "#/features/userList/UserList";

export const Route = createFileRoute("/(core)/users/")({
  component: RouteComponent,
});

function RouteComponent() {
  return <UserListPage />;
}
```

The actual page component (`UserListPage`) lives in `src/features/<FeatureName>/`. Page components follow the `<FeatureName>Page` naming convention.

## Adding a Loader

Data fetching via TanStack Query belongs in the feature. To start a fetch before the page renders (it runs in the browser; SSR is off), use `loader` on the route:

```tsx
export const Route = createFileRoute("/(core)/users/")({
  loader: ({ context: { queryClient } }) =>
    queryClient.ensureQueryData(usersQueryOptions()),
  component: RouteComponent,
});
```

The router context type is defined in `src/routes/__root.tsx` (`MyRouterContext`).

## Route Groups

- `(auth)/` — unauthenticated routes (no app shell)
- `(core)/` — authenticated routes (wrapped in `AppLayout`)

## Auto-generated File

`src/routeTree.gen.ts` is auto-generated by `@tanstack/router-plugin` on every `vite dev` / `vite build`. **Never edit it manually.**

## Client-Side Rendering

SSR is off (`src/start.ts`, `defaultSsr: false`). The root route's `shellComponent` renders only the `<html>` document and `{children}`; the app itself (`AppLayout`, toaster, devtools) is the root `component`, which mounts in the browser. Route `beforeLoad`/`loader` code therefore runs client-side only. Don't put UI back into the shell, or server and client markup will disagree (React error #418).
